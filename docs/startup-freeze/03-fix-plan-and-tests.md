# 03｜证据驱动的最小修复方案及回归门槛

本文件是后续实现指导，不是已完成修复。工作分支仅 fix/startup-freeze-loading，禁止直接修改 main、创建 PR、强制重置或更改签名信息。修复前须核对分支当时最新 HEAD，不能以本次历史 SHA 覆盖之后的代码。

## 第一关：先明确故障发生位置

1. 冷启动、恢复场景分别采集时间线。只加必要的诊断点，记录 Refresh 派发/订阅、历史查询起止、Protobuf 请求起止/结果、reducer 转移及导航点击是否到达。
2. 不记录 Cookie、BDUSS、STOKEN、UID、请求体、用户内容或完整 URL 查询参数；只记录时间、抽象 operation、状态和脱敏错误类型。
3. 若是 ANR，先处理输入阻塞；若主线程健康但主页卡住，先处理加载状态机。仅在确有证据时改动全屏 Dialog / BottomSheet。
4. 若真机 APK 不是基线对应构建，先找到实际构建 SHA；不要把 main 的代码直接视为故障版本。

## 第二关：待证实后实施的定点修复候选

### A. 初始化事件可靠性

- 在 arch/BaseViewModel.kt / arch/Extensions.kt 增加确保首个 Refresh 被接收的明确生命周期契约，不建议盲目给所有意图 SharedFlow 设置 replay=1（可能重放删除、收藏等有副作用的命令）。
- 针对首次订阅时序、旋转、导航重入、ViewModel 复用写测试，验证一次初始 Refresh 恰好执行一次。
- 保证无论数据源正常、异常、空完成、取消，都不会将首页永久留在 isLoading=true；取消应避免错误覆盖新请求。

### B. 首页本地数据和网络请求隔离

- 在 HomeViewModel 中给历史结果与关注吧 API 独立状态或独立结果汇合策略；本地数据不要因为远程 API 超时被无限阻塞。
- 记录请求耗时，按真实网络情况设业务层超时，区分连接/读取/写入与整个调用截止时间。
- 失败时保留已有可展示的列表，首次无数据才显示明确错误和重试入口；网络恢复后能重新加载。
- 保持现有按吧 ID 排序/置顶/历史并集语义，不因拆分 zip 改变列表顺序或账号权限范围。
- 对空返回、403/401、500、错误 protobuf、无法 DNS、超时、数据库查询失败分别回归。

### C. 全局交互无响应

- 拿到主线程 ANR 栈后逐级定位同步 IPC、数据库读取、设备标识、剪贴板读取、Theme 恢复、自动签到与 Compose 主线程负载；不在无证据时全盘迁移线程。
- 若 InputDispatcher 显示独立窗口截获事件，才检查 AnyPopDialog 全屏 Spacer、DialogState.show 的保存/恢复与退出动画、剪贴板弹窗、ModalBottomSheetLayout 的 scrim。
- 保证在主页 Loading / Error / Empty 状态，顶部搜索及底部导航仍可点击；弹窗退出时输入窗口及时释放。

## 第三关：自动化测试需求

| 用例 | 预期行为 |
| --- | --- |
| 初始订阅按极端时序启动 | Refresh 被接收，最终出现非 Loading 状态 |
| 历史查询慢/异常 | 不阻止可独立展示的数据；状态终止且有诊断 |
| 远程请求一直不返回 | 在明确时限内退出 Loading，提示可重试 |
| HTTP 失败 / 登录失效 / DNS 错误 | 不永久骨架；正确错误分类 |
| 网络先慢后快、连续下拉刷新 | 旧结果不得覆盖新结果；取消安全 |
| 远程空结果、上游 Flow 空完成 | 最终 Empty 或 Error，不能永久 Loading |
| 恢复前台、Activity 重建 | 无重复敏感操作或丢失首个刷新 |
| Loading 时点击顶部搜索和底栏 | 交互独立有效 |
| Dialog 创建后退出/恢复 | 无透明触摸屏障残留 |
| 本地历史及关注吧正常数据 | 置顶、排序、计数与历史展示不回归 |

使用现有项目测试基础设施，优先新增可替换数据源的 ViewModel 测试 + Compose UI 点击回归，必要时才引入 MockWebServer 等依赖。保留原有 OxygenOS 7.1.1 UI，不改变 Toolbar/BottomNavigation 布局或视觉风格。

## 后续修复验收

- 无数据与离线场景下能离开骨架屏，出现可操作错误/空状态并可重试。
- 网络正常时首页可加载，加载中搜索及底部导航持续响应。
- 真机多次冷启动、长时间前后台切换、重连与会话过期均没有复现点击全部失效。
- 提供单元/界面回归结果及 Actions 编译结果；说明未覆盖的真机限制。
- 证据不足时只提交诊断与文档，不作「完全修复」声明。
